# Review: Timeline (fe-ops, e62f05fe), live data, 1440×900 + 390

Structure matches OpsLists: h1 `LAST 24H`, `1H · 6H · 24H`, kind filters, E1 density strip, an
hour-grouped log with marks, no horizontal scroll at 390. The content is the problem: the log is
mostly machine events.

1. **Raw event names, no entity** (High): rows read `Source Watermark Advanced` / `Catalog Revision
   Registered` (Title Case from the event key). Speak flight, in sentences, naming what the event is
   about, with a link: "Flight events source caught up to 22:28:57Z", "Catalog rev 2 registered by
   Mira K.", "VBAT below red limit on EARENDIL-001". Unknown kinds fall back to the sentence-case
   key + entity, never Title Case.
2. **Noise drowns signal** (High): ~200 watermark rows in two minutes. Group consecutive identical
   events (same kind + entity) into one expandable row: `Flight events source advanced × 214 ·
   22:28:30–22:28:57Z` (the "1,000 identical findings → one line" principle). Watermark moves are
   data-pipeline housekeeping. Consider defaulting them off under a `Data pipeline` kind (or
   `Configuration`), shown on demand.
3. **Retreated = caution needs a reason:** keep the caution mark only if a watermark retreat means
   something for the operator (replayed or late data), and then say it: "Flight events source went back
   to 22:28:30Z (data replay)". Otherwise neutral.
4. **Filter chips have no visible state:** all six look the same, so which kinds are on? Use the
   chip toggle pattern: `aria-pressed`, white fill (or a ✓) when on, and say `All kinds` when none is
   narrowed.
5. **E1 density strip has no axis:** add the time ticks and labels (`−24H … NOW`, like ApTimeRange)
   and the now-line, so the spike can be read. Brush to narrow (spec) can come later.
