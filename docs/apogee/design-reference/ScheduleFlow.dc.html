Contact scheduling · end to end

Schedule the fleet, not a spacecraft

Today you pick one spacecraft from a grid of 500 cards, and the schedule sits 4,000 px further down. In the new flow, you start from demand. Each profile says how often its spacecraft must be heard from. Cadence drafts the fleet's whole day against every provider's opportunities, and the planner only works the exceptions.

The six stations

01 · PROFILE RULES

Demand

Each profile sets its contacts per day, the longest gap allowed, and how many passes must be able to uplink.

Exit: a need per spacecraft
02 · PROVIDERS

Opportunities

Visibility windows from each provider's antennas, with price, elevation and uplink capability.

Exit: a pool of windows
03 · CADENCE + PLANNER

Draft

The scheduler fills demand at the lowest cost. The planner fixes only the spacecraft it couldn't satisfy.

Exit: every rule met
04 · PROVIDERS

Reserve

One submit sends every booking. Confirmations, rejections and price changes come back on the same plan.

Exit: confirmed at freeze
05 · NETWORK

Fly

Passes run on the live view. If a station drops, the affected passes are re-planned as a single revision.

Exit: realized
06 · PLANNER + FINANCE

Reconcile

Planned against realized: bytes, minutes and money. Missed passes that weren't our fault become disputes.

Exit: billed = flown
