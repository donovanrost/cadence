# CCSDS conformance evidence

This directory keeps conformance evidence separate from the dependency-free
runtime library. It is evidence for the implemented subset, not a claim of
flight qualification or complete CCSDS conformance.

`normative_vectors.exs` is the maintained corpus. Every entry has a stable ID,
an exact publication and SHA-256, a section/table/page locator, and one of
three provenance classes:

- `published_octets` reproduces a short octet sequence printed by a standard;
- `normative_table` reproduces a normative table row; and
- `normative_derivation` records a reviewed byte encoding derived from a
  published bit layout where the standard supplies no worked octet vector.

The corpus intentionally does not vendor the CCSDS PDFs. The recorded URLs and
hashes make the source snapshot independently retrievable and auditable.

## Deterministic generative checks

The normal test suite runs seeded property checks over Space Packets, TC, TM,
and AOS transfer frames, FECF, AOS FHEC, BCH, LDPC, CLTU, randomization,
streaming boundaries, USLP Version-4 framing, and arbitrary malformed inputs. Increase the case count
or reproduce a failure with:

```sh
CCSDS_GENERATIVE_CASES=10000 CCSDS_GENERATIVE_SEED=20260720 \
  mix test test/cadence/ccsds/generative_conformance_test.exs
```

## External interoperability

`hermes/run.sh` performs a bidirectional differential run against NASA Hermes
v4.0.11 at commit `433a8f9fc69a078eb430dab01285d7644e78eb07`. The run covers
Space Packets, Type-BD TC transfer frames with FECF, and fixed-length TM
transfer frames with and without secondary headers. Cadence-generated bytes
are decoded and independently re-encoded by Hermes; Hermes-generated bytes
are then decoded by Cadence.

The harness requires Git, Go 1.26 or newer, and network access on its first run.
It clones the pinned external source under `${TMPDIR:-/tmp}` and never adds it
to this application:

```sh
bash conformance/hermes/run.sh
```

`hermes/evidence.md` records the last maintained run. External interoperability
is deliberately opt-in rather than part of `mix precommit`, because a normal
library build must neither download tools nor depend on an external service.

The issue-5 AOS FHEC vectors are also cross-checked against Yamcs at a pinned
commit. This is narrower independent evidence rather than full AOS
interoperability; see `aos/evidence.md`.

USLP evidence is currently source-hashed and normative rather than
cross-implementation; see `uslp/evidence.md` for the exact boundary.
