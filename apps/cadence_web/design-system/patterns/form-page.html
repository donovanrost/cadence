Form page

The canonical create / edit screen. A width-constrained max-w-2xl stack: a <.page_header> over a <.form for={@form}> of numbered <section> groups of <.input> fields, closed by an actions row. Notably, Cadence forms are bare sections, not card-wrapped — the hud-label divider headings carry the structure.

Anatomy

  • max-w-2xl wrapperForms are narrow (max-w-xl/2xl) — a single readable column, not the full-bleed width of a list.
  • <.page_header>Title ("New Transport" / "Edit …"), subtitle, and breadcrumbs (never a back link) to where Cancel returns.
  • <.form for={@form}>Wires phx-change="validate" + phx-submit="save"; space-y-8 between sections.
  • <.form_section>The numbered heading is a component, not raw markup — number="01" + title render the hud-label + h-px divider. Fields stack single-column inside.
  • <.input> fieldsEach renders its hud-label and inline errors; mark required fields required.
  • <.form_actions>The footer is a component too: border-t + :md primary type="submit" and a ghost Cancel via cancel_navigate.

Usage

  • ✓ Constrain the width (max-w-xl/max-w-2xl) and stack fields in one column — forms read top-to-bottom.
  • ✓ Compose with <.form_section> / <.form_actions> — never hand-roll the numbered headings or the footer row; reach for sections once a form has more than ~4 fields.
  • ✓ Wire phx-change="validate" + phx-submit="save". <.input> renders inline errors from changeset-backed forms once a field is touched — the specimen shows the target. Today's transport/spacecraft forms bind plain maps and error via flash; migrating them to changesets is an open backlog item.
  • ✗ Don't wrap form sections in a <.card> — card chrome is for read views; the divider headings structure a form.
  • ✗ Don't lay fields in multi-column grids — it breaks the scan path and the label/value rhythm.
