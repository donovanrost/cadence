List page

The most-repeated screen in Cadence. A space-y-6 stack of a <.page_header> over a flush <.card padding={:none}> that wraps <.toolbar> → <.table> → <.pagination>. The components own markup and events; the LiveView owns state, URL, and data. When the list is empty, the card is replaced wholesale by <.empty_state>.

Anatomy

  • <.page_header>Breadcrumbs (never a back link), title, :title_suffix count, subtitle, and a primary action in :actions. Sits above the border-b border-primary/20 rule.
  • <.card padding={:none}>Flush frame so the bands sit edge-to-edge — toolbar's border-b and pagination's border-t draw the dividers.
  • <.toolbar>Debounced search on the left; :filters and :actions slots when a list needs them (the shipped pages are search-only). A summary band of <.stat_tile> filters above the card is a documented variant (spacecraft roster).
  • <.table>Name cell links to the show page; sortable headers; mono columns for identifiers and versions.
  • <.pagination>Range label + Prev/Next. Renders nothing when everything fits one page.
  • <.empty_state>Replaces the whole card when there are zero rows — never an empty table with headers.

Usage

  • ✓ Keep all list state in the URL (?q=&filter=&sort=&dir=&page=) via push_patch — shareable and back-button-safe.
  • ✓ Components emit events ("search", "sort", "paginate"); the LiveView owns the fetch. Parse with CadenceWeb.ListParams.
  • ✓ Show <.empty_state> for a truly empty list; show an inline "no matches" line when a search filters everything out.
  • ✗ Don't pad the card — it must be padding={:none} so the bands sit flush against the toolbar/pagination borders.
  • ✗ Don't reach for the toolbar/pagination on organizationally-bounded lists (missions, profiles) that can't exceed a screenful — adopt them opportunistically.
