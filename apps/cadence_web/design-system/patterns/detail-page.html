Anatomy

  • <.page_header>Identity of the record: breadcrumbs, the title, a key identifier in :title_suffix (or the raw ID in subtitle, as transport show does). Record-level actions go in :actions when a page has them — the shipped shows keep actions in their bands' CTAs instead.
  • workflow row(spacecraft show) xl:grid-cols-3 of plain <.card>s — each pairs a <.status_badge> (the sole status signal) with a value and a "go fix it" CTA. Surfaces setup state before the details.
  • main / sidebar split(transport show) xl:grid-cols-[1fr_22rem] — the main card (a <.section_header> with a badge in its actions) beside a narrow companion for related collections or activity.
  • <.card title="Overview">The definition block — hud-data-row pairs in a md:grid-cols-2 grid; full-width rows use col-span-2. Spacecraft show renders it full-width as the closing band.

Usage

  • ✓ Put the record's key identifier in :title_suffix (SCID, version); long opaque IDs go in subtitle. Never bury identity in the body.
  • ✓ Lead with the workflow row when a record has setup state; the <.status_badge> inside the card is the one status signal — no colored card border, no corner brackets.
  • ✓ Build definition data from <.detail_row> / hud-data-row so labels and monospace values stay consistent.
  • ✗ Don't hand-roll key/value markup per page — that's how label styling and mono alignment drift.
  • ✗ Don't duplicate "up" navigation in the body; breadcrumbs/back own going up, CTA links own going deeper.
