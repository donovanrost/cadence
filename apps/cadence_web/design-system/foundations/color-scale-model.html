Color scale model

◎ Proposed — the two-tier color system. The matured Color palette card becomes its primitive reference.

A mature palette is two tiers: primitives (the raw ramps, named by hue) and semantics (the roles, named by job). Components touch only semantics. This is the color-specific instance of the skin / outfit / body architecture — and it's what retires the alpha-faking and the badge drift the contrast audit caught.

Why primitives stay hue-named: one hue serves multiple roles. cyan-500 is --color-action and --chart-series-1 and --border-focus. A primitive named --action couldn't honestly be a chart line. Meaning lives one tier up.

Derivation — oklch does the work

/* one base hue + lightness/chroma offsets — relative-color syntax derives the rest.
   No 11 hand-picked hex values; the ramp is computed and stays perceptually even. */
--cyan-500: oklch(80% 0.12 210);                          /* the anchor */
--cyan-600: oklch(from var(--cyan-500) 70% 0.13 h);       /* darker, hue locked */
--cyan-400: oklch(from var(--cyan-500) 85% 0.10 h);       /* lighter */
/* rule: vary L on a fixed ladder, keep H constant, nudge C so saturation
   reads even (chroma peaks mid-lightness, tapers at the extremes). */

The job matrix — why ~6 steps, not 11

Each chromatic color must cover a fixed set of jobs: text-on-dark · fill · on-fill · border · subtle-surface · muted. That's the ramp's size — defined by what the color must do, not by a convention. A step with no job doesn't get authored; that restraint is the maturity, and it keeps the closed-set discipline the frozen-CSS rule used to enforce crudely.

Coherence — how the color cards relate

Color palette = the primitive reference (the ramps as swatches — it should grow from today's single values into these ramps). This card = the model (tiers, derivation, jobs, semantics). The color semantics here extend the Outfit layer in Semantic tokens — same tier, more color roles. Three cards, three jobs, no overlap.
