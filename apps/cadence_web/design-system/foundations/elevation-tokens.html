Elevation tokens (spec)

✓ Implemented — these depth tokens are live in tokens.css (elevation levels, state films, highlights, sunken shadow, blur reserve). Broad component consumption is Phase 5.

The visual half of layering. It does three things: un-fuses the 7-surface ladder into elevation / role / state, adds the missing depth cue (the lit top edge), and reserves blur to things that actually float. The point: make elevation something a reader can measure off the screen.

1 — Elevation levels (aliases over surfaces)

/* :root — named LEVELS, pointing at the existing surface scale (Outfit-style).
   Components reference the level, not the raw surface. */
--elevation-sunken:   var(--surface-inset);     /* 10% — wells */
--elevation-base:     var(--surface-base);       /* 12% — the page */
--elevation-raised:   var(--surface-raised);     /* 17% — cards, panels */
--elevation-floating: var(--surface-elevated);   /* 23% — popovers, menus */
--elevation-modal:    var(--surface-elevated);   /* 23% — dialogs (+ scrim + blur) */

Four perceptible levels (floating & modal share a surface, differ by blur/scrim). This consolidates the imperceptible 12 / 15 / 17 micro-steps into rungs that actually read.

2 — Separate role & state (the structural fix)

/* ROLE: input is not a rung — it references a level. */
--surface-input: var(--elevation-sunken);   /* commit: a recessed well */

/* STATE: hover/pressed are translucent FILMS, not absolute surfaces.
   They lighten whatever they're on, so they can never out-elevate a higher layer. */
--state-hover:    oklch(100% 0 0 / 0.05);
--state-pressed:  oklch(100% 0 0 / 0.09);
--state-selected: oklch(from var(--color-action) l c h / 0.12);

✓ Decision A — DECIDED: input is a recessed well. --surface-input: var(--elevation-sunken) — every field sits darker than its container (consistent on base and on cards), the "type into a slot" metaphor. Resolves today's contradiction (token 15% but rendered 18%, reading raised). The recessed direction is locked; the exact depth stays tunable.

✓ Decision B — DECIDED: hover is a state-layer film. --state-hover / -pressed / -selected as translucent overlays replace the absolute --surface-hover (27%) — which today is lighter than a floating dropdown (23%), so a hovered row out-elevates an open menu. A film is relative by construction (a ::after overlay or color-mix), so it can't. Applies to every hover state — tables, menus, nav, tiles — a real migration when reconciled.

3 — Depth cues (the missing half + blur discipline)

/* TOP-EDGE HIGHLIGHT — the "lit from above" cue, generalized from btn-primary.
   Stronger as elevation rises. THIS is what Cadence is missing on surfaces. */
--highlight-raised:   inset 0 1px 0 oklch(100% 0 0 / 0.06);
--highlight-floating: inset 0 1px 0 oklch(100% 0 0 / 0.10);

/* SUNKEN — inverts the highlight into a dark inset: the "pressed-in" cue for wells. */
--shadow-sunken:      inset 0 2px 4px oklch(0% 0 0 / 0.35);

/* BLUR — floating & modal ONLY. Remove it from in-flow .hud-panel. */
--blur-floating: blur(8px);
--blur-modal:    blur(12px);

What it fixes

✓ Hover no longer out-elevates overlays (state-film is relative). ✓ Elevation now reads (the top-highlight gives the lit-edge cue tint alone can't). ✓ Blur stops leaking onto in-flow panels. ✓ Inputs become consistent. ✓ The ladder is un-fused — roles & states reference levels.

Rules

  • ✓ Components reference a level (--elevation-raised), never a raw --surface-*.
  • ✓ Raised & up get the matching --highlight-*; only floating & modal get blur.
  • ✓ Hover / pressed / selected are films (--state-*) layered over the element's own surface.
  • ✗ Don't swap an element's surface on hover — that's the absolute-hover bug; use the film.
  • ✗ Don't add a new elevation rung unless it represents a distinct behavior — shade alone isn't a level.

Fits the frozen-CSS rule: new :root tokens + value-tuning existing declarations (add the highlight, move blur, point input/hover at the new tokens) — no new selectors.
