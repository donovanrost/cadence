Reduced motion (spec)

✓ Implemented (2026-06-27) — now a single block in app.css. (There was zero handling before this; only vendor daisyui.js had any.)

The single most important accessibility fix outstanding. The standard: remove non-essential motion when the OS asks — but never remove meaning. The audit below shows the gap is small; one block covers ~all of it, and there's exactly one design decision worth making deliberately.

The audit — everything that moves

What movesCountClassReduced-motion treatment
hud-pulse / -warning / -critical, mc-pulse ×25decorative loop (status liveness)STOP
animate-pulse1decorative loopSTOP
transition-colors / all / glow / box-shadow~70functional feedback (hover, focus)INSTANT
sidebar width + opacity~7functional spatial (collapse/expand)INSTANT (snap)
critical status (the 0.5s strobe)—motion was the salienceSUBSTITUTE static cue

"Instant" means the transition still happens (state still changes) — it just doesn't tween. Nothing is lost except the in-between frames.

The applied block — now in app.css

/* app.css — one media block handles the whole audit */
@media (prefers-reduced-motion: reduce) {
  /* 1. kill the named decorative loops (pairs with Effect tokens) */
  :root { --pulse-nominal: none; --pulse-warning: none; --pulse-critical: none; }

  /* 2. global safety net — instant transitions & animations everywhere */
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

Why 0.01ms and not 0: some JS waits on transitionend / animationend events — a near-zero duration still fires them, a zero duration may not. This is the well-worn accessible pattern.

The one decision — critical loses its salience

△ Stopping the strobe removes critical's salience (urgency draw), not its meaning (color + shape still say "critical"). For nominal & warning that's fine. For critical, motion was the salience — a static red dot is easy to miss in an anomaly. So reduced-motion should substitute a static high-salience cue, not just delete the animation:

critical · strobing (motion on)static ring (your OS has reduce-motion on) 
@media (prefers-reduced-motion: reduce) {
  .hud-status-critical .hud-status-dot {
    animation: none;
    /* salience was the strobe → give it a static ring instead */
    box-shadow: 0 0 0 3px oklch(from var(--status-critical) l c h / 0.45),
                0 0 6px oklch(from var(--status-critical) l c h / 0.8);
  }
}

Decision made: nominal/warning just stop; critical gets the static ring (applied). The demo dot above is live proof — it strobes normally, and freezes into the ring if your OS reduce-motion setting is on.

How to verify

OS: macOS Accessibility → Display → Reduce motion; Windows Accessibility → Visual effects → Animation; iOS/Android equivalents. Browser: devtools "Emulate prefers-reduced-motion: reduce." Then confirm the pulses freeze, transitions snap, and the critical ring appears.

Rules

  • ✓ Decorative loops off; functional transitions instant (they still change state, just don't tween).
  • ✓ Use 0.01ms, not 0, so JS *end events still fire.
  • ✓ Where motion was the salience (critical), substitute a static cue — don't just delete it.
  • ✗ Don't gate essential meaning behind motion in the first place — color + shape must already carry it.
  • ✗ Don't override scroll/focus behaviour users rely on for orientation beyond what's needed.

✓ Shipped as one media block in app.css + the critical substitute. No component changes, no new selectors. Verify by toggling your OS reduce-motion setting.
