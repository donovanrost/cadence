Foundations

Motion

✓ Durations, pulses, the easing system, and reduced-motion are all current — --duration-*/--ease-* live in tokens.css; the @media block lives in app.css.

Motion has exactly four jobs: orient (where did this come from / go), feedback (you did a thing), continuity (this is the same object moving), and liveness (it's alive and updating). Anything else is decoration — and in a console read under stress, decoration competes with the data. The rule that follows: motion must point at what changed, never make the screen a disco.

Duration current

/* short by design — ops users act fast; over ~400ms reads as sluggish */
--duration-fast:   150ms;  /* instant feedback: hover, color, border */
--duration-normal: 200ms;  /* state change: reveal, expand, toggle */
--duration-slow:   300ms;  /* spatial: drawer, sheet, larger moves */

These are your existing --transition-fast / normal / smooth (0.15 / 0.2 / 0.3) — just documented with a purpose per tier. One refinement: today duration and easing are fused in --transition-*; separating them (--duration-* + --ease-*) lets you compose “200ms + ease-out” freely.

Easing

--ease-out:      cubic-bezier(0.0, 0, 0.2, 1);   /* ENTERING — decelerate */
--ease-in:       cubic-bezier(0.4, 0, 1, 1);     /* LEAVING — accelerate */
--ease-standard: cubic-bezier(0.4, 0, 0.2, 1);   /* MOVING in-view (your --transition-smooth) */
--ease-linear:   linear;                         /* continuous loops: spin, pulse, progress */
CurveUse forWhy
ease-outthings appearing (menus, popovers, reveals)fast start feels responsive; gentle landing
ease-inthings leaving (dismiss, collapse)accelerates away; you don't watch it go
ease-standardthings moving within view (drawer, reorder)symmetric, calm
ease-linearlooping liveness (pulse, spinner)no accel — a loop must read as constant

Today Cadence has one curve (the standard) and otherwise default ease. The gap is enter vs exit: appearing should decelerate, leaving should accelerate. That single distinction is what makes motion feel intentional rather than generic.

Liveness — the status pulses current

nominal · 2s breathe warning · 1s blink critical · 0.5s strobe

Looping motion = liveness only, and urgency is encoded by speed: calm breathe → fast strobe. It's the most attention-grabbing (and expensive) motion you have — reserve it for status. The full animation shorthands live as the --pulse-* knobs in Effect tokens; this is their motion meaning.

⚠ The critical 0.5s strobe (opacity + scale) is a genuine photosensitivity / fatigue risk in a 24/7 room — which is exactly why the next section is non-negotiable.

Reduced motion

/* refined: kill decorative LOOPS, make functional transitions instant.
   Pairs with the --pulse-* knobs in Effect tokens. */
@media (prefers-reduced-motion: reduce) {
  :root { --pulse-nominal: none; --pulse-warning: none; --pulse-critical: none; }
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

Shipped in app.css — decorative loops stop, functional transitions go near-instant (0.01ms so JS transitionend still fires), and the critical dot swaps its strobe for a static ring. The rule that makes it safe: removing motion must never remove meaning. When the pulse stops, the status dot keeps its color and shape, so urgency still reads. (Try it: this card's dots above freeze if your OS has reduce-motion on.)

Rules

  • ✓ Every animation earns one of the four jobs (orient / feedback / continuity / liveness). No job → cut it.
  • ✓ Keep it short — 150–300ms. Let easing carry direction: ease-out in, ease-in out.
  • ✓ Looping motion is liveness only; dial urgency by speed; honor prefers-reduced-motion always.
  • ✗ Don't animate many things at once — under stress, motion should isolate what changed.
  • ✗ Don't let motion remove meaning when it stops, and don't use it as decoration — the data is the figure.

Fits the frozen-CSS rule: new :root tokens (durations split, easing curves) + a reduced-motion media block reassigning tokens — no new component selectors.
