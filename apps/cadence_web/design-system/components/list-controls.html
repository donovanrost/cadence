List controls

The fleet-scale list pair from ListControls: <.toolbar> is the search row at the top of a flush card, <.pagination> the matching footer. They own markup and event emission only — the LiveView owns state, URL, and data fetch. The search box emits "search" with %{"q" => term}, debounced 300 ms; Prev/Next emit "paginate" with %{"page" => n}.

Usage

  • ✓ The URL is the source of truth for list state: translate "search"/"sort"/"paginate" into push_patch so ?q=&sort=&dir=&page=&filter= stays shareable and back-button-safe. Parse with CadenceWeb.ListParams.
  • ✓ Search is debounced (debounce default 300) and emits %{"q" => term}; reset page: 1 on a new query so results don't land on a stale page.
  • ✓ The toolbar lives inside the flush card (<.card padding={:none}>) directly above <.table>; <.pagination> is the matching footer fed by Cadence.Listing.Page fields.
  • ✓ Adopt these only when a list can realistically exceed a screenful — organizationally bounded lists (missions, profiles, catalog) can skip them.
  • ✗ Don't build "Page 1 of 1" chrome or hide the footer by hand — <.pagination> already renders nothing when everything fits on one page.
  • ✗ Don't keep search/sort/page in socket-only assigns — a list state that isn't in the URL can't be shared, bookmarked, or restored by the back button.
