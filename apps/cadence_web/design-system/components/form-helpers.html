Form helpers

The two composition helpers from CadenceWeb.Components.Forms. <.form_section> renders a numbered hud-label heading — number (text-primary/70), title, h-px divider — over a space-y-4 body of fields. <.form_actions> is the canonical footer: a :md primary submit and an optional ghost Cancel over border-t border-base-300/60 pt-5. Sections stack with space-y-8 inside a max-w-2xl form.

Attributes

  • form_section numberRequired string, zero-padded ("01", "02"…); renders as hud-label text-primary/70.
  • form_section titleRequired string; the hud-label <h2> before the h-px bg-base-300/60 divider.
  • form_actions submitSubmit label, default "Save"; submit_type defaults to "submit".
  • form_actions cancel_navigateOptional path; when set, renders a ghost Cancel (cancel_label, default "Cancel") that navigates back.
  • inner_block / classBoth helpers take class; extra actions in form_actions' block render after Cancel.

Usage

  • ✓ Always compose forms from <.form_section> and <.form_actions> — never hand-roll the numbered heading or footer as raw <section> markup.
  • ✓ One primary :md submit per form, paired with a ghost Cancel via cancel_navigate back to where the user came from.
  • ✓ Keep forms narrow (max-w-2xl) and single-column, with space-y-8 between sections; fields inside get space-y-4 for free.
  • ✗ Don't wrap sections in a <.card> — Cadence forms are bare; the hud-label divider headings carry the structure.
  • ✗ Don't add a second primary button or put destructive actions in the footer row — extra actions go in the inner block as ghost/secondary.
